# 按需元数据搜索实施计划

目标：规划器遇到候选范围缺表时，自主搜索同一已发布快照，继续读取字段详情并生成计划；不执行SQL、不改本体。

1. 在 `ontology_core/metadata_lookup.py` 增加 `search(query)`：查询最多500字符，每次返回相关对象，索引与详情分层。合并对象、表族到当前候选上下文；总候选扩展设上限，返回截断提示，禁止跨快照。
2. 在 `tools/metadata_lookup.py` 注册 `search_metadata`：有搜索能力时允许三轮只读工具交互及一次最终响应，每轮至多四次工具调用；保留旧纯详情接口的一轮行为。不自动重试失败计划。
3. 在 `tools/llm_client.py` 指示模型缺字段时先搜索，再规划；同步说明新增候选可用于计划，搜索未命中不等于本体不存在。
4. 测试：搜索扩展及详情可读、参数校验、连续搜索/详情/最终结果流程。只运行相关纯单元测试，不写会话数据库，不调用DeepSeek。
5. 提交改动、正常权限重启后端并检查就绪。

边界：本次使用现有词法索引，模型自行选搜索词和关联候选；不增加硬编码业务表映射。自主搜索在SQL规划工具内部，尚不向外层普通问答开放。候选扩展上限32张，每次搜索最多8张；既有超限明确表仍保留。字段详情单次最多64项。

## 实施记录

已实现搜索、候选合并、按需字段详情、三轮工具预算与提示词接入。20项相关检查通过，使用合成元数据与模拟模型响应，无真实模型调用或会话数据库写入。

难点：只把搜索结果发给模型还不够，确定性校验仍会拒绝原候选外的引用。解决方式是在同一个快照绑定的查询对象内扩展候选，并复用原有 `lookup.enriched()` 交给校验器；已返回的字段详情同步保留。未放宽版本一致性或SQL校验。

真实会话效果尚待复测；词法搜索仍可能受字段别名与描述质量影响，增加搜索工具不意味着保证最终SQL正确。
