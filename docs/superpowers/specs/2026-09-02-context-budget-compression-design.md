# 动态上下文预算与低频压缩设计

## 目标

让智能取数会话把历史输入输出提供给本轮全部大模型调用，同时只在预计下一轮上下文超过有效预算时压缩。多数普通会话不触发压缩，数据库中的原始消息永不因压缩而删除或改写。

## 决策

- 使用统一 `ContextAssembler` 组装历史，程序规划、规划修复、口径推导和旧 SQL 生成复用同一份会话上下文。
- 模型上下文上限、静态提示预留、触发比例和目标比例均可配置；首期默认上下文上限 32768、输出 4096、静态提示预留 8192、触发 80%、目标 60%。
- 有效历史预算为 `context_window_tokens - max_tokens - static_prompt_reserve_tokens`。只有“已有摘要 + 未压缩历史 + 本轮固定上下文”的估算 Token 达到有效历史预算的 80% 才压缩。
- 压缩时完整保留最近 6 轮（最多 12 条用户/助手消息），只总结更早内容。摘要优先保存目标、已确认口径、表字段关系、账期、用户纠正、最新有效 SQL 和未决问题。
- 压缩调用失败时使用确定性的提取式回退；不得让压缩失败阻断取数。
- 摘要及其消息边界持久化在会话记录中。后续请求使用“摘要 + 边界后的原始消息”，避免反复总结同一段历史。
- 如果当前请求本身过大，不截断用户本轮输入；压缩器只处理旧历史。

## 数据流

1. API 从数据库读取全部历史消息及已有摘要边界。
2. `ContextAssembler` 估算本轮历史 Token。
3. 未到 80%：原样返回已有摘要与全部未压缩历史。
4. 达到 80%：保留最近 6 轮，压缩更早消息，并尽量降到 60%。
5. API 持久化新摘要边界，将组装结果传给 `run_agent`。
6. 本轮所有模型调用收到同一份组装结果；UI 仍展示完整原始会话。

## 验收

- 短会话不调用摘要模型，历史不被裁剪。
- 长会话只压缩旧消息，最近 6 轮保持原文。
- 摘要失败时仍能继续生成。
- 已压缩消息下一轮不重复送入摘要模型。
- 程序规划、修复、口径推导和 SQL 生成都能看到组装后的会话上下文。
