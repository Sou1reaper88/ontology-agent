# 智能取数三栏证据工作台设计

## 目标

将现有智能取数页重构为“会话目录 → 需求与 SQL → 本体依据”的三栏工作台，让用户能够直接看到本体如何影响表映射、业务口径、关联关系和业务账期。本阶段只调整前端表现与组件边界，不修改 Agent、接口、认证、查询执行、本体规划或数据模型。

## 现状问题

- `Chat.tsx` 同时承担接口调用、轮询、会话管理、消息渲染、SQL 编辑和批量删除，文件超过 700 行且存在大量内联样式。
- 用户消息、智能体回答、生成链路、SQL 和本体证据堆叠在同一个灰色消息块中，阅读层级不清晰。
- `OntologyComparison` 使用蓝、紫、绿等多种卡片边框和标签，与“理性研究台”的单一青绿色强调体系冲突。
- 本体依据只附着在消息底部。消息较长时，用户难以同时核对 SQL 与依据。
- “本体未命中”主要表现为一条 Alert，不能帮助用户理解缺少的是对象、口径、关系还是可用链路。
- 页面依赖固定视口高度和固定侧栏宽度，窄屏下缺少可靠的证据查看方式。

## 方案

采用三栏证据工作台：

1. 左侧会话目录保留现有新建、选择、批量删除、清空和单条删除功能；
2. 中间是主要工作区，按需求、回答、生成链路、SQL 对比和执行操作组织消息；
3. 右侧是当前选中智能体回答的本体证据检查器。

桌面宽度不足时，右侧检查器不继续压缩主工作区，而由“查看本体依据”按钮打开抽屉。手机宽度下会话目录也改为抽屉入口，主工作区始终优先。

## 视觉与信息层级

### 会话目录

- 使用较窄的暖灰表面和清晰分隔，不再依赖白色 Card 阴影。
- 当前会话使用青绿色浅底和左侧标记；批量选择使用中性选中态，危险色仅用于最终删除动作。
- 会话标题为主信息，最后一条消息和更新时间为次信息。
- 空状态直接提供“新建需求”入口。

### 主要工作区

- 顶部显示当前会话标题、上下文状态和上下文设置入口。
- 用户需求使用紧凑的右对齐强调块；智能体回答使用无气泡的报告式排版，以留白和分隔线组织内容。
- 生成链路默认折叠成一行状态摘要；展开后显示步骤、耗时和错误节点，避免链路长期占据主要视线。
- SQL 对比保留“现有 Agent SQL”和“本体驱动 SQL”两条结果，但改为同一比较区域：
  - 明确标注现有 SQL 可编辑、可执行；
  - 明确标注本体 SQL 为只读影子预览；
  - 表映射变化和内容是否变化放在比较区顶部；
  - SQL 使用统一等宽字体、行距和操作栏，不再使用紫色边框。
- 输入区固定在主工作区底部，保留 Enter 发送、Shift+Enter 换行和现有占位说明。

### 本体证据检查器

检查器由当前选中的智能体回答驱动，按以下顺序展示：

1. 本体状态与摘要；
2. 业务账期决策；
3. 概念、属性、关系、规则、数据源和映射证据；
4. 本体包 ID、版本和摘要指纹。

当结果为 `generated` 时，状态显示为“本体已参与生成”。当结果不是 `generated` 时，不推断后端未返回的信息，只根据现有稳定状态展示：

- `no_match`：未找到可用本体对象或属性；
- `ambiguous`：存在多个候选，无法唯一选择；
- `unsupported`：已识别语义，但当前映射或编译能力不支持；
- `unavailable`：本体影子链路不可用；
- `clarification_required`：需求存在需要用户确认的业务账期冲突。

后端 `summary` 作为具体说明原样展示。前端不自行猜测更细的缺口类型，也不修改 SQL 生成结果。

## 选择与数据流

- `Chat.tsx` 继续持有会话、消息、轮询、发送、编辑和执行状态，是唯一业务控制器。
- 展示组件只通过 Props 接收数据和回调，不直接调用 API。
- 每条带 `ontology_shadow` 的智能体回答提供“查看本体依据”动作。
- 页面初次加载或切换会话时，默认选择最新一条带本体结果的智能体回答。
- 用户主动选择一条回答后，只要该消息仍存在就保持选择；消息刷新后若该消息不存在，再回退到最新可用结果。
- 桌面端右栏立即更新；窄屏端同一动作同时打开证据抽屉。
- 没有任何本体结果时，检查器展示说明性空状态，不伪造命中数据。

## 组件边界

- `Chat.tsx`：业务状态、API、副作用和页面编排。
- `ConversationSidebar`：会话列表与批量操作的纯展示组件。
- `TraceSteps`：生成链路折叠与步骤展示。
- `MessageTimeline`：消息报告布局、SQL 编辑入口和操作回调。
- `OntologyComparison`：只负责两条 SQL 的比较与操作，不再承载完整证据清单。
- `OntologyEvidencePanel`：本体状态、时间决策、证据和包版本。
- `evidenceSelection`：根据消息和用户选择确定当前证据消息的纯函数。
- `Chat.css`：三栏布局、消息排版、SQL 表面、抽屉适配和响应式规则。

组件拆分只迁移表现逻辑，不改变接口请求顺序、轮询时机、消息 DTO 或错误处理语义。

## 加载、空状态与错误

- 会话列表加载使用与列表行形状一致的骨架，不使用覆盖整个侧栏的居中 Spin。
- 消息加载使用报告行骨架；生成中的消息继续显示实时链路步骤。
- 没有选择会话时，中间区域展示开始新需求的明确入口。
- 会话加载、删除、发送、轮询和执行仍沿用现有后端错误文案与消息提示，本阶段不改错误协议。
- 本体非生成状态在证据检查器中展示，不将 `no_match` 等正常安全状态渲染为系统故障。

## 响应式与无障碍

- 大屏：左侧会话目录、中间工作区、右侧证据检查器同时可见。
- 中等宽度：右侧证据检查器改为抽屉，主工作区与会话目录保留。
- 手机宽度：会话目录和证据检查器均为抽屉，主工作区单列展示。
- 所有删除、选择、展开、复制、编辑、执行和打开抽屉操作使用真实按钮。
- 当前会话、当前证据选择、加载和错误状态不仅依赖颜色表达。
- SQL 区域支持换行与横向滚动，不在窄屏裁切内容。

## 测试与验收

- 为证据消息选择规则增加纯 TypeScript 契约测试，覆盖默认最新、保持用户选择、失效回退和无证据状态。
- 保留并运行现有前端契约测试。
- TypeScript 与 Vite production build 必须通过。
- 运行态只验证本次核心路径：打开智能取数页、切换会话、选择带本体结果的回答、查看 SQL 对比、打开证据抽屉以及已有编辑/复制/执行入口仍可见。
- 完成后保留 `127.0.0.1:5199` 服务，由用户先做视觉和交互验收，再决定第三块本体工作台改造。

## 非目标

- 不重写 Chat 的 API、副作用或轮询实现；
- 不修改本体结果 DTO、后端状态或 SQL 文本；
- 不增加 SQL diff 算法、语法高亮库、Markdown 渲染器或新的前端依赖；
- 不在本阶段改造本体管理、数据查询、结果或管理页面内部结构；
- 不处理现有生产包体积警告。
