# 本体草稿导入格式提示与动态样例设计

## 1. 背景

当前本体包工作台的“导入草稿”区域只提供文件选择和预览按钮，没有说明支持格式、大小限制、标准列或填写规则，也没有可下载的填写样例。现有 XLSX 解析器默认第一行就是字段表头，不能识别用户提供的实际格式：第一行为说明、第二行为对象与属性分组标题、第三行才是十列标准表头。

本功能补齐可见的导入契约和可直接填写的动态 XLSX 样例，同时让解析器兼容单对象、多对象共用的实际工作簿布局。

## 2. 已确认决策

- Python 后端动态生成样例，不提交静态 XLSX 文件。
- 页面提供“单对象样例”和“多对象样例”两种下载入口。
- 用户附件只作为版式参考，其真实表名、字段名、描述和数据不进入源码、测试或 Git。
- XLSX 保持单工作表结构：第一行说明、第二行分组标题、第三行十列标准表头、第四行起为数据。
- 十个标准列必须全部存在且名称不可修改。
- 对象英文名称在每个属性行必填；对象中文名称和状态在每个对象中至少填写一次。
- 属性英文名、属性中文名和属性类型每行必填。
- 是否主键、是否标题允许留空，留空按“否”处理。
- 对象描述和属性描述可空。
- 下载模板不读取或修改草稿，不改变修订号。
- 实现完成后运行必要的针对性测试和构建，自动 Git 提交，不自动推送或合并；随后启动服务供用户优先验收。

## 3. 目标与非目标

### 3.1 目标

1. 用户无需猜测即可看到支持格式、大小限制和主要填写规则。
2. 用户可以下载单对象或多对象 XLSX 样例，替换虚拟内容后直接上传预览。
3. 模板生成与导入解析共用一份格式契约，避免列名和规则漂移。
4. 解析器能够安全、确定地识别带说明行和分组行的工作簿。
5. 错误提示包含工作表、行号和字段名，但不回显整行业务数据。

### 3.2 非目标

- 不导入或提交用户提供的两个参考附件。
- 不支持 `.xls`、`.xlsm`、宏、外部链接或加密工作簿。
- 不改变“预览后显式确认”的原子导入流程。
- 不增加 CSV 格式。
- 不在本阶段设计数据库直连或元数据扫描。

## 4. 统一格式契约

Python 本体管理模块提供唯一的导入格式定义，模板生成器和解析器共同使用。标准列顺序为：

1. 对象英文名称
2. 对象中文名称
3. 对象描述
4. 状态
5. 属性英文名
6. 属性中文名
7. 属性类型
8. 属性描述
9. 是否主键
10. 是否标题

所有十列都必须出现在表头中，且不得存在同名重复列。说明和分组行不属于数据。空白尾列不影响识别，但额外命名列或修改后的标准列使预览失败，防止格式漂移被静默忽略。

对象英文名称用于把连续或交错的数据行归入同一对象。对象中文名称与状态可以只在该对象任一行提供一次；同一对象出现多个互相冲突的非空值时返回待确认或错误，不擅自选择。对象描述采用相同的首个非空值策略，但仍为可选字段。

属性英文名、属性中文名和属性类型是属性行必填值。是否主键、是否标题支持“是、否、1、0、true、false、yes、no”等既有明确布尔写法；空白等价于“否”。无法识别的非空布尔值不得静默按否处理。

## 5. XLSX 模板生成

新增独立的 `ImportTemplateBuilder`，输入模板变体 `single` 或 `multiple`，输出宏-free XLSX 字节和稳定文件名。它只依赖统一格式契约，不依赖工作区草稿。

模板工作表包含：

- 第一行合并 `A1:J1`，写入填写说明和样例替换提示。
- 第二行合并 `A2:D2` 与 `E2:J2`，分别显示“对象元数据信息”和“对象属性信息”。
- 第三行写入十列标准表头，必填列使用醒目的红色文字。
- 第四行起写入纯虚拟样例。单对象变体使用一个虚拟对象，多对象变体使用两个虚拟对象。
- 样例标识只使用 `SAMPLE_OBJECT_A`、`SAMPLE_OBJECT_B`、`FIELD_ID` 等无业务含义值，并明确提示用户替换样例后上传。
- 设置适当列宽、冻结表头和基础样式，保证下载后可读、可编辑。

模板由后端按请求即时生成，不落盘到应用仓库，也不写入工作区管理目录。

## 6. 解析流程

对于每个非空 XLSX 工作表，解析器在前 20 行内寻找包含完整十列标准名称的唯一表头行。识别规则只比较单元格文本，不依赖颜色、合并样式或公式。

- 找到且仅找到一个完整表头：从下一行开始解析数据。
- 未找到完整表头：阻止该文件导入并报告工作表和扫描范围。
- 找到多个完整表头：以歧义格式阻止导入。
- 表头包含重复标准列、缺失标准列、额外命名列或改名列：阻止导入并列出安全的列名诊断。
- 说明行和分组行不作为数据，也不进入诊断内容。

TSV/TXT 仍要求 UTF-8，第一行直接使用相同十列标准表头，不引入说明行或合并结构。XLSX 和 TSV 最终进入同一行级校验流程。

解析器保留现有文件大小、宏、外部链接、加密条目、路径穿越和压缩炸弹检查。位置诊断使用“文件名、工作表、行号、列名”，不返回整行值。

## 7. API

新增工作区级下载接口：

```text
GET /ontology-packages/workspaces/{workspace_id}/imports/template?variant=single|multiple
```

接口沿用本体维护者权限边界。成功响应返回 XLSX 附件及明确文件名；不返回 JSON 包装，不改变草稿修订号。未知变体返回稳定的 `400` 错误；无权限、未知工作区和模板生成失败沿用现有安全错误格式。

## 8. 前端交互

“导入草稿”卡片增加：

- 可见格式提示：支持无宏 `.xlsx`、UTF-8 `.tsv/.txt`，单文件不超过 20 MB，可在同一文件中填写一个或多个对象。
- “下载填写样例”下拉按钮，包含“单对象 XLSX 样例”和“多对象 XLSX 样例”。
- 简短规则：十列列名不可修改；对象级字段每对象至少填写一次；属性级字段按行填写；描述可空；主键和标题留空按否。
- 文件扩展名和明显超限在前端先行提示，后端仍为最终安全边界。

下载动作与已选择文件、当前预览互不影响。下载失败只显示安全提示，不清空文件列表。重新选择上传文件继续使旧预览失效。

## 9. 错误处理

- 模板生成失败：页面显示“样例下载失败”，服务端记录不含业务内容的错误摘要。
- 表头未找到或存在歧义：阻止预览，提示工作表和原因。
- 行级必填值缺失：提示工作表、实际行号和列名。
- 对象级元数据完全缺失：在完成对象分组后报告该对象缺少的字段。
- 非法布尔值或属性类型：不猜测，返回待修正诊断。
- 任意解析或校验失败都不产生可确认令牌，不修改草稿。

## 10. 测试与验收

### 10.1 后端测试

- 单对象和多对象模板具有预期工作表、合并区域、十列表头和虚拟对象数。
- 两种动态模板可被同一解析器重新读取并进入就绪预览。
- 带说明行、分组行和第三行表头的合成工作簿可解析。
- 缺列、改名、重复列、额外命名列、重复表头或无表头时失败关闭。
- 对象级必填值按对象校验，属性级必填值按行校验。
- 主键/标题空白按否，非法非空值被拒绝。
- 模板下载接口权限、响应头、变体校验和草稿修订号不变。
- 测试仅使用合成标识，不读取用户附件。

### 10.2 前端测试

- 格式、大小和填写规则清晰可见。
- 两种下载项调用正确接口并使用服务端文件名。
- 下载失败不影响文件选择和导入预览状态。
- 文件类型和大小的前端提示正确，现有预览确认流程保持有效。

### 10.3 人工验收

1. 启动后端与前端并打开 `/ontology`。
2. 分别下载单对象和多对象样例。
3. 替换虚拟内容后上传，确认对象和字段计数正确。
4. 使用与参考附件一致的第三行表头布局进行预览。
5. 检查缺失必填值和修改列名时的错误定位。
