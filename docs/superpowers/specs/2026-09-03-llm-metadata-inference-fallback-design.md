# 基于元数据的大模型候选推断设计

## 目标

当已发布本体包含表和字段元数据、但尚未定义关系或业务口径时，允许大模型基于表名、表描述、字段名和字段描述提出候选表、候选关联与候选口径，并由 Python 校验和编译为只展示、不执行的 Hive 取数程序。

该链路用于扩大本体建设早期的可用性，不把推断结果伪装成已确认本体事实，也不把推断内容自动写回本体。

## 当前基线

- 2026-09-03 使用数据库中保留的 7 条真实案例重新调用 `run_agent`。
- 7 条均生成脚本，但全部只使用 `D_BBZX_DW_PRODUCT_M`，物理源表集合 0 条完全匹配参考程序。
- 参考 SQL 均为 4–8 条 `DROP + CREATE` 的多步骤 Hive 程序；当前评测器只接受单条只读查询，因此 7 条均被标记为不可评分。
- 新持久化草稿已导入 10 张 GSM 地市详单表、1,270 个字段和 10 条 `P_DAY/T-2` 时间策略；附件未包含宁波分表，所有对象描述为空。

## 适用边界

- 候选推断只能选择已发布元数据中真实存在的对象和字段，不能猜测目录中不存在的物理标识符。
- 关系、口径与表族成员可以推断，但必须同时返回依据、置信等级和未确认项。
- SQL 只生成和展示，不进入执行接口；前端不得把候选结果标记为“本体已确认”。
- 候选结果不自动生成关系、规则或时间策略，不修改草稿或活动版本。
- 如果找不到字段完整、类型兼容且无笛卡尔积的计划，则不输出伪 SQL，返回可行动的缺失信息。

## 方案选择

采用“确定性召回 + 大模型结构化推断 + Python 约束校验 + 确定性编译”。

不采用把全量 Schema 直接交给模型生成 SQL：该方式容易编造物理字段，且 1,000 余字段会稀释注意力。不采用缺少关系即停止：这无法满足本体建设早期仍需得到候选结果的目标。

## 架构

### 1. 元数据候选召回

新增只读候选目录，从活动本体快照读取对象、字段、映射和时间策略。使用需求词与中文标签、描述、别名进行确定性粗排，先选对象，再选每个对象的相关字段。召回结果携带稳定对象/字段引用，不允许模型直接输入任意物理名称。

目录只读取不可变活动版本。草稿必须先发布才能被取数智能体使用，从而保持评测可复现。

### 2. 结构化候选推断

新增 `InferredProgramDraft` 合同，要求模型输出：

- 候选对象及选择理由；
- 请求输出字段；
- 候选过滤条件及自然语言口径；
- 候选关联两端的对象/字段稳定引用及推断依据；
- 表族选择（单成员、指定成员或全部成员）；
- 用户时间表达或是否使用默认时间策略；
- 每项推断的 `high`、`medium`、`low` 置信等级；
- 未确认项和本体补充建议。

模型不输出 SQL、目标表名或目录之外的对象/字段。

### 3. Python 候选校验

校验器拒绝下列计划：

- 对象或字段引用不在活动快照；
- 多表计划缺少连接条件；
- 连接字段类型明显不兼容；
- 产生无条件笛卡尔积；
- 过滤值既不来自用户需求，也没有字段描述或已发布规则作为依据；
- 表族成员字段集合或分区策略不兼容；
- 时间条件无法落到一个安全有界账期。

关系未确认本身不阻断候选 SQL，只降低置信等级并写入证据。

### 4. 地市分表族

字段集合、字段类型、时间策略一致，且物理名仅地域段不同的对象可组成候选表族。需求指定地市时只选对应成员；需求覆盖全省时对所有已发布成员生成 `UNION ALL` 中间步骤，再继续过滤、关联和物化结果。

系统只能报告当前活动版本中的成员，不能凭命名规律补造缺失的宁波表。

### 5. 编排与状态

执行优先级：

1. 已确认本体规划成功：`program` / `repaired_program`；
2. 本体对象存在但关系或口径不足：进入候选推断；
3. 候选计划通过校验：`inferred_program`；
4. 候选计划无法安全绑定：返回缺失信息；
5. 旧 SQL 链路只保留为显式兼容路径，不再作为默认静默回退。

`inferred_program` 输出必须显示“LLM 推断、未经本体确认、不可自动执行”，并展示候选依据、置信等级、未确认项和本体改进建议。

## 评测要求

- 评测适配器记录生成模式，分别统计确认本体与候选推断生成率。
- 参考 SQL 和候选 SQL 均按多步骤程序解析，忽略系统生成的临时目标表名，比较最终源表、字段、过滤、关联、分区和查询形态。
- 基线中的 7 条案例继续保留，补表或补关系后新建评测任务，不覆盖历史结果。

## 验收标准

- 只有表字段元数据、没有关系和口径时，可以输出通过物理标识校验的候选程序。
- 候选输出不包含目录外表名或字段名，不产生笛卡尔积，不进入执行接口。
- 全省 GSM 需求可识别同构地市表族并生成 `UNION ALL`；指定地市只使用对应成员。
- 所有推断均有依据、置信等级和改进建议，且不写回本体。
- 没有任何可验证连接依据时返回缺失信息，而不是编造 SQL。
- 多步骤真实 SQL 可以进入结构评测，不再统一标记 `reference_parse_failed`。
