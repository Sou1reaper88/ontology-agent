# 本体关系编辑搜索设计

## 背景与目标

关系编辑器当前一次加载草稿中的全部对象、字段和关系，但四个端点选择器只能滚动选择，现有关系列表也无法筛选。对象和字段增多后，维护人员难以快速定位中文业务名称或物理标识。

本阶段在前端增加本地搜索，不改变本体草稿、后端 API、权限或修订号机制。搜索必须覆盖关系创建和已有关系查找两条路径。

## 范围

### 包含

- 源对象、源字段、目标对象、目标字段下拉框支持搜索。
- 对象和字段均可按中文名称或物理名称匹配。
- 现有关系支持按关系标签、源/目标对象名称及源/目标字段名称筛选。
- 中文名称和物理名称均使用去除首尾空格、不区分英文大小写的包含匹配。
- 清空搜索词恢复完整关系列表。
- 无匹配结果时显示明确的空状态。
- 已删除端点继续显示并可通过“已删除对象或字段”状态匹配。

### 不包含

- 不新增后端搜索接口、分页或数据库索引。
- 不改变关系保存、确认、基数、权限和并发冲突逻辑。
- 不跨工作区搜索，不搜索已发布版本中的历史关系。
- 不引入新的通用 UI 组件体系。

## 方案选择

采用前端本地搜索。当前对象、字段和关系已经随工作区概览全量加载，本地筛选响应最快，也不会产生额外接口请求。

未采用通用搜索组件，因为当前只有关系编辑器需要这组组合索引，抽象 UI 组件会增加不必要的依赖。未采用后端搜索接口，因为现有数据边界没有分页，新增接口无法减少传输或内存占用。

## 交互设计

四个端点选择器开启可输入搜索。下拉选项继续展示“中文名（物理名）”；输入任一名称片段即可过滤，英文物理名不区分大小写。字段选择器仍必须先选择所属对象，切换对象时继续清空对应字段值。

“现有关系”标题下增加搜索框，提示可搜索关系标签、对象或字段。输入时即时过滤，不触发网络请求，也不影响上方正在填写的关系表单。搜索词为空时显示全部关系；有搜索词但无结果时显示“未找到匹配关系”；原始关系列表为空时仍显示“尚未配置关系”。

## 组件与数据流

新增一个无 React 依赖的轻量搜索模块，包含：

- 文本标准化函数：处理空值、首尾空格和英文大小写。
- 对象/字段选项匹配函数：同时匹配标签和物理名。
- 关系搜索文本生成或匹配函数：组合关系标签、两端对象标签/物理名、两端字段标签/物理名。

`RelationPanel` 负责：

1. 保存关系列表搜索词。
2. 使用 `useMemo` 根据搜索词、对象和关系列表计算展示结果。
3. 为四个 `Select` 配置显式 `filterOption`，调用相同的标准化匹配口径。
4. 将筛选后的数组交给现有 `List` 渲染。

后端数据流保持不变：工作区概览返回对象和关系，搜索只读取这些内存数据，不写入草稿。

## 异常与边界

- 标签为空时只匹配物理名。
- 搜索词仅包含空格时等同于清空搜索。
- 对象或字段引用已失效时，列表展示和搜索均使用“已删除对象或字段”。
- 搜索不会自动选择选项，也不会清空已选值；只有用户切换对象时沿用现有逻辑清空从属字段。
- 保存期间搜索仍可输入，但不会影响已经通过表单校验的提交数据。

## 测试与验收

纯函数契约测试覆盖：

- 中文标签包含匹配。
- 英文物理名大小写不敏感匹配。
- 关系标签匹配。
- 源端和目标端对象/字段匹配。
- 空白搜索词返回全部关系。
- 无结果和已删除端点场景。

前端生产构建必须通过。运行态验收在本体工作台完成：验证四个选择器均可搜索，关系列表可筛选和清空，搜索过程不产生工作区写请求且草稿修订号保持不变。

## 完成标准

- 维护人员无需滚动遍历即可按业务名称或物理名称定位对象和字段。
- 已有关系可通过关系本身或任一端点信息定位。
- 搜索不改变任何本体数据和现有关系编辑安全边界。
- 自动化契约测试、前端构建和一条真实页面搜索路径通过。
