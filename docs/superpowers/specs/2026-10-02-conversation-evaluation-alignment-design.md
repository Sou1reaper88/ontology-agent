# 当前智能取数链路评测对齐设计

日期：2026-10-02

## 目标与边界

评测中心对新建任务调用与智能取数会话相同的 `run_conversation_agent`，并能分析单条只读查询及多步 `DROP TABLE IF EXISTS` / `CREATE TABLE AS SELECT` 脚本。输入仍为“需求原文、真实 SQL”，输出仍为逐案例结果、六维差异和汇总。只生成与静态分析，不执行 SQL，不创建会话或取数执行记录，不自动重跑现有七条真实需求。已存历史评测记录及原始 SQL 原样保留。

## 方案选择

采用无会话副作用的生成适配器直接调用当前对话智能体，并复用现有评测任务、导入、结果持久化和六维比较器。它使用与新会话首轮一致的空历史上下文、固定系统时间和当前本体快照；不通过 HTTP 新建临时会话。后者会污染历史、审计和用户反馈，且需要清理。只抽取最后一条 CTAS 也不可取：中间步骤使用的业务源表、条件和关联会消失。

## 生成与可追溯性

- 新任务默认使用当前单模型工具链。一次案例只调用一次该链路；不在评测器里追加自动修复或第二个模型裁判。
- `sql` 非空但交付校验失败时保留草稿和失败诊断，不记作“生成成功”，也不评分为业务正确。
- 从生成过程记录模型响应状态、所用本体包标识和耗时。运行时仍以本体包摘要锁定一整个评测任务，版本变化就停止后续案例。
- 新任务写入评测引擎标识 `conversation-v1`；旧任务未带此标识，仍按旧结果显示，禁止把两套不同生成链路的分数混称为同一基线。可复用任务现有 JSON 汇总字段，不新增数据库迁移。

## SQL 分析与评分

- 用现有 `sqlglot` 和 `evaluation.sql_structure` 的只读查询提取能力。分析器只读 AST，不连接业务数据源。
- 接受单条只读查询，或可识别的多步 CTAS 程序；参考 SQL 可以使用自己的临时表名。CTAS 每一步记录目标表、查询、依赖与物理来源；最终结果取最后一个被交付的查询/结果表。仅统计能追溯到最终结果的步骤，不把无关临时表算作需求内容。
- 将临时表引用沿依赖图展开为底层物理表；比较最终投影、聚合与结果形态，以及可追溯步骤中的源表、关联、过滤和分区条件。临时表的随机名称不参与差异比较。
- 只在字段与关联来源足够明确、两边结构都解析成功时沿用六维评分。别名/字段血缘无法可靠追溯、复杂表达式语义无法安全归一、程序不符合支持形态或解析失败时，分数为 `null`，标记“需人工复核”并保留原 SQL 与可读诊断；绝不把不完整展开结果算作严格通过。
- 支持的脚本语句仅用于分析 CTAS、其配对 DROP 和末尾只读查询；UPDATE、INSERT 等其他写入语句不评分。生成端仍须通过现有交付安全校验，本设计不放宽生成权限。

## 页面与历史兼容

新任务的页面标识为“当前智能取数链路”，隐藏无意义的 Legacy 分数；旧任务继续按原标签展示已有结果。案例详情保留需求、真实 SQL、模型 SQL、诊断和人工复核状态。导入模板和原有 API 路径不变。

## 验证

先写失败测试，再实现：模拟对话模型返回只读查询、合规双步 CTAS、未通过校验草稿、提供方失败和本体版本变化；用合成 SQL 覆盖中间表依赖、不同临时表命名、无关步骤、不能解析的字段血缘及不支持的写入语句。检查旧任务展示与新任务标识。只跑聚焦后端测试、前端契约/构建和本地服务就绪；不调用付费模型、不执行七条真实需求或任何业务 SQL。
