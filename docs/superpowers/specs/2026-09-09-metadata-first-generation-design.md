# 元数据优先生成链路设计

## 背景

当前已发布本体包以导入的表、字段、字段描述、关系和时间策略为主，包含约 2,000 个字段。生成链路却先把整个语义目录交给旧式结构化计划器；真实测试中该调用约 210 秒后不可用。随后元数据候选推断已能选择相关对象，但模型偶发返回被 Markdown 或说明文字包裹的 JSON，导致本应由本体校验处理的候选计划提前失败。

## 目标

让元数据候选推断成为智能取数的首选路径：先以检索后的少量候选表、字段、关系和时间策略生成 SQL 程序；成功即返回。只有候选推断无法生成可编译程序时，才尝试既有语义计划器。单次请求不得对相同候选上下文重复调用候选推断。

## 设计

### 生成路由

`ProgramGenerationService.generate` 在确认活动本体可用后，优先调用 `_infer`。若候选推断生成并安全编译出 SQL，直接返回 `INFERRED_PROGRAM`；若本体快照不可用，直接返回不可用状态。候选无命中、候选计划无效或确定性校验失败时，保留其安全诊断，继续尝试既有语义计划器。

语义计划器成功时不显示先前候选阶段的失败，避免干扰用户；语义计划器同样无法生成时，最终结果合并两阶段的安全诊断和缺失信息。此时不再次调用 `_infer`，避免重复消耗模型 token。

### JSON 契约

结构化计划和元数据候选计划仍必须通过现有 Pydantic 模型校验；不会接收 SQL、物理表名、未知字段或额外字段。客户端只做无语义的 JSON 外壳归一化：剥离完整 Markdown JSON 围栏，或提取响应中唯一、完整的顶层 JSON 对象。对象以外的内容会被忽略，解析后的对象仍必须完整通过原有严格 Schema。

元数据工具调用请求与普通结构化请求统一携带 `temperature` 和已解析的 `max_tokens`，并在最终响应提示“首尾必须为 JSON 对象、不得附加说明”。

### 安全与可观测性

不记录、不展示模型原文、用户业务内容或内部推理。诊断继续只使用稳定分类：服务不可用、无效 JSON、Schema 不符合、确定性本体校验失败。SQL 仅输出，绝不自动执行。

## 验收标准

1. 有候选元数据时，候选推断在旧式语义计划器之前执行；候选成功时后者不调用。
2. 候选失败后语义计划器最多调用一次，且候选推断不重复调用。
3. Markdown 围栏或纯说明前缀包裹的完整 JSON 能被归一化；JSON 对象仍必须通过严格 Pydantic 校验。
4. 工具调用轮次传递模型温度和输出上限。
5. 目标单元测试和完整 Python 测试套件通过；随后用第 1 条真实测试需求复测，记录结果但不执行 SQL。
