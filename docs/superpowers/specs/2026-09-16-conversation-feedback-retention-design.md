# 会话反馈留存设计

## 目标

为包含 SQL 的智能体回答增加最小反馈闭环，允许用户标记“结果正确”或“需要修改”，留存补充口径和最终 SQL，并由本体维护人员集中查看。

本阶段只解决反馈留存和人工复盘，不建设自动 Reflection、高频口径识别、跨会话语义聚类、候选知识生成或本体自动修改。

## 产品边界

- 仅已完成且包含 SQL 的 assistant 消息显示反馈入口。
- “结果正确”一键保存，最终 SQL 使用当前生成 SQL。
- “需要修改”必须填写问题说明或补充口径；最终 SQL 可选，默认带入当前生成 SQL供用户修改。
- 同一条 assistant 消息只保留一份反馈，后续提交更新原记录。
- 删除或清空会话时，关联反馈随消息一起删除。
- 已人工写入本体草稿或已发布本体的知识不受会话删除影响。
- 普通问答、生成中的回答和不含 SQL 的回答不提供反馈入口。
- 提交和查看反馈不会触发任何 LLM 调用。

## 数据模型

新增消息反馈表，每条记录包含：

- 唯一标识；
- assistant 消息 ID，唯一且外键级联删除；
- 提交用户 ID；
- 状态：`correct` 或 `needs_revision`；
- 问题说明或补充口径；
- 最终 SQL；
- 创建时间和更新时间。

原始需求、会话编号、消息编号、生成 SQL、trace 和本体版本继续从关联消息及其会话读取，不重复保存快照。这样既避免数据副本不一致，也保证删除会话时完整清除反馈证据。

## 接口与权限

反馈写接口采用消息级 upsert：

- 后端确认消息属于当前用户的会话；
- 后端确认消息角色为 assistant、生成已完成且包含 SQL；
- `correct` 自动采用原始生成 SQL；
- `needs_revision` 要求非空说明，最终 SQL允许为空；
- 重复提交更新已有反馈。

用户可以读取、修改和撤销自己的反馈。本体维护员和管理员可以在本体工作台读取全部用户反馈；普通用户不能读取其他用户的需求、SQL或反馈内容。本阶段不授予维护员替其他用户修改反馈的能力。

## 前端交互

### 智能取数

在包含 SQL 的已完成回答操作区增加：

- “结果正确”：直接保存并显示已反馈状态；
- “需要修改”：打开紧凑弹窗，填写问题说明或补充口径，可编辑最终 SQL；
- 已反馈后允许重新选择状态或撤销反馈。

错误反馈保留页面当前内容，显示可操作提示，不静默覆盖本地输入。

### 本体工作台

新增“反馈记录”阶段，集中展示：

- 反馈状态；
- 会话和消息编号；
- 原始需求；
- 问题说明或补充口径；
- 最终 SQL；
- 生成时使用的本体版本；
- 提交用户和时间。

首版提供状态筛选、详情查看和原会话定位，不提供自动写入本体按钮。维护人员需要沉淀知识时，可复制会话/消息编号，在智能取数对话中让模型分析本体修改建议，再人工编辑本体草稿。

## 自动账期界面删减

从本体工作台移除“自动账期”阶段及顶部“时间策略”统计，因为当前规则不可在页面修改。后端和发布链路继续保留以下行为：

- `_D` 表使用 `P_DAY`，默认系统日期减两天；
- `_M` 表使用 `P_MON`，默认上一个完整自然月；
- 需求明确指定账期时优先使用用户值；
- 历史本体中的时间策略和底层兼容接口保持不变。

若诊断原本导航到自动账期阶段，改为导航到对应对象详情或诊断列表，不产生失效页面。

## 数据流

1. 用户查看包含 SQL 的 assistant 回答。
2. 用户提交正确或需要修改反馈。
3. 后端验证所有权、消息状态和输入约束后 upsert 反馈。
4. 会话详情返回该消息的反馈状态，刷新历史会话后仍可见。
5. 本体维护员在本体工作台读取聚合反馈列表并人工复盘。
6. 用户删除会话时，消息和反馈由数据库外键级联删除。

## 错误处理

- 消息不存在、无权访问或已随会话删除时统一返回不可枚举的未找到响应。
- 生成中、普通问答或无 SQL 消息拒绝提交反馈。
- `needs_revision` 缺少说明时返回明确校验错误。
- 数据库保存失败不改变页面原有回答和用户填写内容。
- 本体版本无法从历史 trace 提取时显示“未记录”，不阻止反馈留存。

## 验证范围

只执行与本功能成比例的验证：

- 后端：正确反馈、修改反馈、upsert、越权、无 SQL拒绝和会话删除级联；
- 前端：反馈状态展示、修改弹窗、失败保留输入、工作台列表与自动账期入口移除；
- 运行前端构建检查；
- 启动共享服务，验证反馈提交、历史恢复和集中查看。

不重跑七条真实需求，不调用付费模型，不执行业务 SQL，也不进行无关模块的全量审查。

## 明确不做

- LLM 自动判断高频口径；
- 跨会话需求聚类或需求族管理；
- 定时 Reflection 任务；
- 自动生成候选知识；
- 自动修改或发布本体；
- 独立知识库或向量数据库；
- 为未来自动学习预留抽象接口。
