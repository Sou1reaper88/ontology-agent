# 本体对象列表与详情页改造设计

## 目标

解决当前“对象目录 + 字段编辑表格”并排导致字段描述空间过窄的问题，将对象选择与对象详情拆成两个清晰层级。用户先从对象列表选择表，再进入完整宽度的对象详情，查看表名、表描述、字段和字段描述。

本阶段只改造“对象与字段”阶段的前端信息架构与表现，不修改后端接口、草稿模型、修订冲突协议、级联删除或字段保存行为。

## 方案选择

采用“工作台内列表与详情分层 + URL 查询参数”的方案：

- 对象列表与对象详情不再同时显示；
- 点击对象后，右侧活动阶段区域切换为完整宽度详情；
- 当前对象 ID 写入 `/ontology?object=<encoded-id>`，支持刷新、复制链接和浏览器前进后退；
- 返回对象列表时移除 `object` 查询参数；
- 本体工作台状态栏、资产概览和阶段导航继续保留，避免进入详情后失去本体包上下文。

未采用独立 `/ontology/objects/:id` 路由，因为对象 ID 可能是 URI，路径编码与嵌套路由会增加不必要复杂度，并导致工作区加载与布局重复。未继续使用抽屉，因为抽屉无法解决字段描述宽度不足，也不适合承载完整字段目录。

## 对象列表

“对象与字段”阶段默认展示对象目录：

- 顶部显示对象总数、字段总数和搜索框；
- 对象以可点击行或紧凑目录项展示中文名、物理表名、描述摘要、字段数量与状态；
- 支持按中文名、物理表名和表描述搜索；
- 点击任一对象进入详情；
- 空草稿显示导入引导，不展示空白字段区域；
- 列表层不提供字段编辑，避免选择与编辑职责混杂。

## 对象详情

详情页分为三部分：

1. **返回与定位**：显示“对象与字段 / 当前对象”层级和返回对象列表操作。
2. **对象信息**：完整展示中文表名、物理表名、表描述、字段数量和状态。
3. **字段目录**：使用详情区完整宽度展示物理字段名、类型、中文名、字段描述、主键与标题字段标识。

默认进入只读模式。点击“编辑对象与字段”后：

- 对象中文名和表描述变为可编辑控件；
- 字段中文名和字段描述变为可编辑控件；
- 对象信息使用现有对象更新接口保存；
- 字段继续按行使用现有字段更新接口保存；
- 删除对象和删除字段保留现有精确名称确认弹窗；
- “退出编辑”恢复只读展示，不提交尚未保存的输入。

字段目录保留搜索与分页。字段描述列获得最高伸缩优先级；物理字段名、类型和操作列使用稳定宽度。在窄屏下允许表格横向滚动，不压缩描述到不可读宽度。

## 状态与异常

- URL 中的对象 ID 不存在时，显示“对象已不存在或链接失效”，并提供返回列表；
- 草稿刷新后若当前对象仍存在，继续停留详情；若对象已删除，返回对象列表；
- 修订冲突继续使用工作台现有刷新提示；
- 删除当前对象成功后移除 URL 参数并返回列表；
- 搜索、进入详情、退出详情和切换编辑模式均不产生草稿写入。

## 组件边界

- `ObjectPanel` 改为对象列表控制器，只处理搜索和进入详情；
- 新增 `ObjectDetailPanel`，负责详情只读/编辑状态、对象保存、字段保存与删除入口；
- 新增纯函数处理对象搜索、URL 对象选择和失效回退，便于契约测试；
- `OntologyWorkbench` 继续负责 overview 数据与刷新，不复制任何 API 请求；
- 查询参数由“对象与字段”阶段消费，切换到其他阶段时不展示详情；返回该阶段后仍可依据 URL 恢复对象详情。

## 视觉方向

延续“理性研究台”风格。对象列表强调目录感，不使用等高卡片墙；对象详情使用清晰的标题区、元数据带和宽字段表格。只读态以排版和留白为主，编辑态才出现输入框与保存操作，使浏览和治理状态可以一眼区分。

## 验收标准

- 对象列表与字段详情不再并排；
- 点击对象后可看到完整表名、表描述、字段与字段描述；
- 字段描述在常用桌面宽度下具有明显更宽的可读区域；
- 默认只读，显式点击后进入编辑态；
- URL 可恢复当前对象，浏览器返回可回到列表；
- 对象和字段的保存、删除、冲突处理行为保持不变；
- 搜索与页面切换不修改草稿修订号；
- 前端契约测试和 production build 通过；
- 完成后启动现有服务供用户先验收效果，并自动提交 Git，不推送或合并。
