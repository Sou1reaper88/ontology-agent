# SQL 评测测试集极简模板设计

## 目标

为本体驱动取数智能体建立一份业务人员可直接填写的 Excel 测试集模板。用户只提供需求原文和对应的真实 SQL，后续评测程序负责生成案例标识、解析 SQL 结构并计算评测指标，避免把人工标注工作转嫁给用户。

## 安全边界

- Git 只保存空白模板和通用填写说明。
- 填写后的真实测试集保存在 Git 工作树之外，不提交需求、表名、字段名、业务口径或真实 SQL。
- 模板中不内置真实或合成业务案例，避免样例明文长期残留。

## 工作簿结构

### `测试案例`

仅包含两个需要用户填写的字段：

| 字段 | 必填 | 填写规则 |
| --- | --- | --- |
| 需求原文 | 是 | 保留业务人员提出需求时的完整原始表述，不为迎合系统改写。 |
| 真实SQL | 是 | 填写经人工确认可作为正确答案的完整 SQL；保留换行，多段临时表 SQL 放在同一单元格。 |

工作表提供冻结表头、自动换行、筛选和空值提示，但不增加案例编号、业务域、SQL 方言、账期或人工拆解字段。

### `填写说明`

说明以下规则，不要求用户录入任何信息：

- 一行代表一个测试案例；
- 两列必须同时填写；
- 真实 SQL 应是可作为评测基准的最终版本；
- SQL 结构不必与智能体输出完全相同，后续评测应优先比较表、字段、关系、过滤条件、账期和结果语义；
- 首期导入按当前项目的 Hive SQL 环境处理；未来多平台能力由导入配置指定，不扩张当前模板字段；
- 填写后的文件不得提交 Git。

## 后续导入与评测约定

- 导入程序按行生成稳定案例标识，不要求用户维护编号。
- SQL 解析器从真实 SQL 提取物理表、字段、关联、过滤条件和账期，解析结果允许后续单独校正，但不回写本模板。
- 评测至少输出：生成状态、表命中、字段命中、关系命中、账期命中、SQL 可执行性、结果一致性和失败原因。
- 当前模板只负责采集评测事实，不在本阶段实现批量导入器或评测执行器。

## 校验与验收

- 空白模板可被 Excel 正常打开。
- `测试案例` 只有两个用户输入列，表头清晰、长 SQL 可换行阅读。
- `填写说明` 明确安全边界和填写规则。
- 工作簿不包含业务表名、字段名、口径或示例 SQL。
- 生成后检查关键单元格、公式错误和所有工作表的视觉布局。
