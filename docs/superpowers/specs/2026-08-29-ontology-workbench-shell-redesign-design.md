# 本体工作台框架与阶段导航改造设计

## 目标

将现有纵向堆叠的本体包管理页面改造为能够表达本体构建流程的工作台。用户进入页面后，应立即看清当前本体包、草稿状态、活动版本、资产规模，以及接下来应处理的阶段。

本阶段只调整前端信息架构与视觉表现，不修改后端接口、本体数据模型、草稿修订协议、导入行为、诊断规则或发布流程。

## 范围

本阶段包含：

- 重构工作台头部，集中展示本体包名称、活动版本、草稿修订和刷新状态；
- 将对象、字段、关系和时间策略统计整理为紧凑的资产概览；
- 新增固定的阶段导航，依次呈现“导入元数据、对象与字段、关系、时间策略、诊断、发布版本”；
- 右侧操作区一次聚焦一个阶段，复用现有业务组件；
- 根据现有数据计算阶段摘要和状态提示，不新增后端字段；
- 保持窄屏可用，阶段导航在小屏下转换为横向可滚动导航；
- 补充加载、空数据和刷新反馈，使页面状态清晰可辨。

本阶段不包含：

- 重写对象、关系、时间策略、诊断和版本组件内部表单；
- 修改导入模板、关系搜索、级联删除等既有业务行为；
- 新增或修改本体管理 API；
- 改造聊天、数据查询或管理后台页面。

## 信息架构

页面分为三层：

1. **工作区状态栏**：展示本体包名称、活动版本、草稿修订号和刷新入口。状态信息使用清晰文本而非分散的彩色标签。
2. **资产概览带**：展示对象、字段、关系、时间策略四项统计，用于快速判断本体包覆盖程度。
3. **构建工作区**：左侧为阶段导航，右侧为当前阶段内容。选择阶段只改变前端展示，不改变路由和后端状态。

阶段导航与现有组件映射如下：

| 阶段 | 现有组件 | 摘要来源 |
| --- | --- | --- |
| 导入元数据 | `ImportPanel` | 草稿修订、对象与字段数量 |
| 对象与字段 | `ObjectPanel` | 对象与字段数量 |
| 关系 | `RelationPanel` | 关系数量 |
| 时间策略 | `TemporalPanel` | 时间策略数量 |
| 诊断 | `DiagnosticsPanel` | 各严重级别诊断数量 |
| 发布版本 | `VersionPanel` | 活动版本与历史版本数量 |

首次进入默认打开“对象与字段”；若草稿没有对象，则默认打开“导入元数据”，避免用户面对无内容的编辑器。

## 交互与状态

- 点击阶段导航后，右侧内容就地切换，不滚动长页面；
- 当前阶段具有明确选中态，并展示阶段编号、名称和数据摘要；
- 后端刷新期间保留现有内容，状态栏显示刷新反馈，避免整页闪烁；
- 草稿修订冲突仍沿用现有刷新与提示逻辑；
- 兼容说明降级为工作区内的次要说明，不再占据首屏主要空间；
- 所有已有保存、删除、发布、回滚和导入确认行为保持不变。

## 视觉方向

延续已确认的“理性研究台”风格：冷静的蓝灰中性色、单一蓝色强调、清晰的数字排版和轻量分隔。工作台依靠层级、留白和选中状态组织信息，避免继续堆叠同质 Ant Design 卡片。

不引入新的 UI 依赖，不使用装饰性渐变或大面积阴影。新增样式进入本体工作台专用样式文件，尽量移除入口组件中的内联布局样式。

## 组件边界

`OntologyWorkbench` 继续负责数据加载、刷新、修订冲突处理和阶段选择。现有六个业务面板继续负责各自的表单与 API 行为。本阶段可以增加纯展示组件和阶段配置模块，但不得把业务请求复制到新组件中。

阶段配置使用稳定键值，导航与面板通过同一映射生成，避免标题、顺序和内容分支分散维护。

## 验收标准

- 首屏能看清本体包状态、资产规模和六个构建阶段；
- 不再需要纵向滚动整页寻找关系、时间策略、诊断或版本功能；
- 空草稿默认引导至导入，有数据的草稿默认进入对象与字段；
- 六个现有面板的 API 与操作行为保持不变；
- 桌面和窄屏均可访问全部阶段；
- 前端构建通过，开发服务保持运行，供用户优先进行视觉与交互验收；
- 完成后记录本轮信息架构难点、取舍与解决方式，并自动创建 Git 提交。

## 后续边界

用户验收本阶段后，再决定下一块是优先重构“对象与字段编辑器”，还是调整工作台框架。本设计不为尚未确认的编辑器重构预先增加抽象。
