# 本体草稿原子级联删除设计

## 背景与目标

本体管理后端已经支持删除未发布、未被引用的草稿对象和字段，但前端没有删除入口；对象或字段一旦被关系、时间策略引用，现有接口只能拒绝删除。用户需要在明确了解影响范围后，一次性删除目标及其草稿引用，同时保持已发布本体标识不可变。

本阶段补齐管理员可见的对象、字段删除能力。删除必须可预览、需二次确认、在一个草稿修订中原子完成，并留下不含业务内容的审计记录。

## 范围

### 包含

- 对象删除影响预览与原子级联删除。
- 字段删除影响预览与原子级联删除。
- 级联移除引用目标的草稿关系与时间策略。
- 前端删除按钮、影响摘要、物理名称确认和错误反馈。
- 管理员权限、修订冲突、已发布标识保护和审计。

### 不包含

- 删除或改写不可变 RDF 已发布版本。
- 通用批量变更集、回收站或一键撤销。
- 维护者删除权限。
- 自动恢复被删除的草稿内容。

## 方案选择

采用后端原子级联删除。前端不串行调用关系、时间策略和对象删除接口，也不引入通用变更集接口。

该方案让后端在同一个修订事务中重新计算影响并完成全部删除，避免中途失败留下半完成草稿。前端展示的数量仅用于确认，不作为后端决策依据。

## 权限与不可变边界

- 只有“全省管理员”可以预览和执行删除。
- 本体维护者及其他角色均不得删除。
- 目标对象一旦使用过已发布对象标识，整个删除请求失败。
- 删除字段时，目标对象或目标字段任一标识已发布，整个删除请求失败。
- 发布版本本身不被修改；普通草稿删除不能绕过稳定标识保护。
- 请求必须携带当前 `expected_revision`，过期请求返回草稿修订冲突。

## 影响计算

### 删除对象

影响集合包含：

- 目标对象一个；
- 目标对象拥有的全部字段；
- 源对象或目标对象为该对象的全部草稿关系；
- 归属于该对象的时间策略。

### 删除字段

影响集合包含：

- 目标字段一个；
- 源字段或目标字段为该字段的全部草稿关系；
- 使用该字段作为分区字段的时间策略。

影响集合必须由后端根据当前草稿计算。执行删除时再次计算，并与当前修订一起验证。

## API 设计

在现有对象和字段资源下增加删除影响预览接口：

- `GET /ontology-packages/workspaces/{workspace_id}/objects/{object_id}/delete-impact`
- `GET /ontology-packages/workspaces/{workspace_id}/fields/{field_id}/delete-impact`

响应返回目标类型、物理名称、对象数、字段数、关系数、时间策略数和当前修订号，不返回字段取值或其他业务数据。

现有 `DELETE` 接口扩展请求体：

```json
{
  "expected_revision": 7,
  "cascade": true,
  "confirmation_name": "D_SAMPLE_OBJECT"
}
```

后端要求 `cascade=true`，并校验 `confirmation_name` 与当前目标物理名称完全一致。名称不匹配、目标不存在、权限不足、已发布标识或修订冲突均失败关闭。

成功响应沿用草稿写接口结构，返回更新后的修订号及草稿数据。

## 原子删除流程

1. 验证管理员身份与请求结构。
2. 读取当前草稿并校验 `expected_revision`。
3. 定位目标，验证确认名称。
4. 验证目标对象/字段没有已发布稳定标识。
5. 根据当前草稿重新计算关系与时间策略影响集合。
6. 在同一个 copy-on-write 草稿变更中移除引用，再移除字段或对象。
7. 对结果运行草稿结构校验并一次提交新修订。
8. 写入成功或失败审计记录。

任一步失败均不提交部分结果。

## 前端交互

- 对象编辑抽屉增加红色“删除对象”按钮。
- 字段表操作列增加红色“删除”按钮。
- 点击按钮后先请求删除影响预览。
- 弹窗展示将删除的对象、字段、关系和时间策略数量。
- 用户必须输入目标物理名称，名称完全匹配后才可确认。
- 确认期间按钮进入加载状态，防止重复提交。
- 成功后刷新工作区；删除对象时清除失效的对象选择，删除字段时刷新字段表。
- 修订冲突时关闭旧确认状态、刷新工作区并要求重新发起。
- 其他失败直接显示后端提供的安全中文原因。

前端是否显示按钮不能代替后端权限校验。由于当前登录响应不提供可靠角色信息，首期可展示删除入口，由后端返回权限结果；后续若增加用户能力接口，再按能力隐藏或禁用按钮。

## 审计与错误

成功审计记录：工作区、操作类型、目标稳定标识、删除前后修订号，以及对象/字段/关系/时间策略的删除数量。审计不得记录对象描述、字段描述或上传行内容。

稳定错误至少覆盖：权限不足、目标不存在、确认名称不匹配、未开启级联、已发布标识保护和草稿修订冲突。

## 验证策略

- 编辑器测试：无引用删除、单类引用级联、关系与时间策略同时级联、其他对象不受影响、已发布阻止、失败不改变修订。
- API 测试：预览数量、管理员成功、维护者拒绝、确认名称、`cascade`、未知目标、修订冲突和安全错误信封。
- 前端契约测试：路径编码、请求载荷、影响响应映射和修订冲突识别。
- 前端构建验证。
- 运行态核心路径：使用当前分支服务，在真实页面导入合成草稿，创建引用，预览并确认删除，验证页面计数及后端草稿一致。

自动化测试负责代码边界，运行态核心路径负责确认页面连接的是当前服务且完整交互可用；健康检查不能替代功能验收。
