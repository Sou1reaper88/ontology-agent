# 2026-10 项目建设记录

## 评测中心对齐当前智能取数链路

### 难点与原因

评测中心原先调用旧的单条 SQL 生成入口，而聊天界面已经走可由模型调用工具的会话智能体。两处结果无法直接对照。历史评测还同时展示 Legacy 与本体两条路径；新链路实际上只有一份正式交付 SQL。真实案例中的 `DROP TABLE IF EXISTS`、`CREATE TABLE AS SELECT` 多步骤脚本，也不能用只接受单条查询的解析方式可靠评分。

### 解决方式

- 新评测任务逐条调用当前会话智能体；沿用现有上下文装配，但不创建聊天或取数历史记录，不执行生成的 SQL。
- 新任务在已有汇总数据中标记执行链路，前端只展示有意义的当前智能体结果；旧任务及其双路径记录保留原样。
- 基于 SQL 语法树追溯最终结果依赖的临时表，比较物理来源表、过滤、关联和最终输出；临时表名称不同不直接判错。
- 遇到无法可靠追溯的字段血缘或未通过交付校验的草稿，明确标注人工复核，不将其算作零分或有效交付。
- 修复任务刚创建、汇总指标尚未产生时页面读取空数据可能报错的问题。

### 验证与边界

57 项评测相关后端测试、前端展示契约测试及生产构建通过。测试使用合成 SQL 和假模型返回，没有运行七条真实需求、调用付费模型或执行任何业务 SQL。静态结构相似不等于业务口径正确；真实结果仍需人工核验。
