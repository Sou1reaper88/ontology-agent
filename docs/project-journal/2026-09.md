# 2026-09 项目建设记录

## 本体状态在服务重启后丢失

### 现象

本体管理页面曾经能够读取草稿，但服务重启后草稿和活动运行时不可恢复，导致取数链路重新表现为本体不可用。

### 根因

管理状态曾落在临时运行目录，进程生命周期结束后没有稳定的恢复边界；就绪接口还在每次请求时尝试恢复，使启动问题与请求副作用混在一起。

### 解决方式

- 强制通过外部固定目录保存草稿、不可变版本和活动版本指针。
- 拒绝源码仓库、保留目录、系统临时目录和链接路径。
- 在 FastAPI lifespan 中只执行一次活动版本恢复。
- `/ready` 只读取运行时健康状态，并返回脱敏的稳定原因。
- 通过依赖注入保证发布器与查询链路使用同一个只读运行时快照。

### 可复用经验

智能体的本体不是普通缓存，而是生成结果所依赖的可版本化业务资产。仅实现编辑页面和内存加载不等于具备本体工程能力；还需要明确持久化位置、不可变发布、活动指针、启动恢复、快照一致性和备份边界。

### 验证方式

运行持久化路径、发布器、健康检查和管理 API 的聚焦测试；发布一个测试版本后记录版本号与摘要，重启后端并确认两者不变。记录中不保存真实表名、字段、SQL、口径或测试集内容。
